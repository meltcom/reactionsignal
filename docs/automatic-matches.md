# Automatic discovery resolution

Automatic performer policies no longer require a moderator to release identity candidates. New discoveries use `automatic-matches-v1` while saving immutable candidate recognition evidence. Canonical title/narrative reaction evidence and eligible-channel title evidence (exact hashtag, singular performer name, or the existing channel-scoped abbreviation/typo rules) publish automatically. Shorts follow the same identity rules and keep their independent format classification. Candidate recognition itself remains the shared Python/JavaScript evidence-only contract; the disposition is a separate application policy.

Promotional announcements, watch parties, ambiguous contexts and unsupported identity are rejected from the feed automatically. These are match decisions, not permanent exclusions. A moderator can correct them through catalog tools. Automatic classification uses public metadata, not an audiovisual review, and does not guarantee video contents. Generic titles, linked originals, common member names and unrelated uploads never inherit performer identity from their channel.

Every scheduled discovery cycle also resolves up to 50 existing pending matches using one batched videos request (plus bounded retries), with no search requests. Empty queues make no metadata request. Unavailable metadata, channel conflicts and upcoming videos remain pending for automatic retry after six hours. The next scheduled cycle continues larger queues. No moderator action or preview toggle is required. The former scheduled preview pass is replaced to avoid duplicate metadata requests; manually requested previews remain available.

Explicit moderator/manual holds, review-only performer policies, existing final decisions, exclusions and format locks are preserved. Existing pending decisions use a transactional compare-and-set against source, catalog title/format/channel, channel scope and performer aliases/policy. Audit and notification writes require the exact applied source marker, so concurrent decisions cannot be overwritten or falsely recorded. Rejections do not create exclusions. Existing approved catalog videos are not reclassified by this change.

No migrations, search allowance changes or Backfill Catalog configuration changes. Backfill's evidence contract is unchanged; newly staged pending candidates are picked up by the same scheduled resolver. Audit records use `automatic-match:*`, with run counts in `automatic-match-last` and temporary retries in `automatic-match-retry:*`.

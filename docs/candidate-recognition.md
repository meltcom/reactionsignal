# Review-only candidate recognition

The shared `server/candidate-policy.json` manifest drives pure JavaScript and Python adapters. The locked fixtures in `tests/fixtures/ms-candidates` contain 33 observed metadata objects, 25 constructed boundary cases and 24 saved decision controls. Expected outputs identify 18 review candidates (12 strong, six weak), with 12 positive title hints. They are candidate expectations, not verified reactions or measured recall.

Recent/RSS screens accept additional positive title hints. Final metadata processing first preserves the legacy classifier; only otherwise-unmatched Missioned Souls items on currently eligible known channels can receive PENDING from the new policy. Exclusions, existing decisions, channel identity, availability and format locks take precedence. Immutable evidence in candidate-recognition state keys records the policy/version, matched field/reason, input and metadata hash. Candidate-only additions do not create confirmed notifications. Their Candidate review source protects them from metadata-preview promotion, including after a title change; explicit moderator content review remains available. No global aliases, quota limits, schedulers or cursors are changed.

Python uses the same manifest for new unknown metadata and retains its evidence beside the raw response. Known IDs still skip metadata calls; seen IDs are not automatically reclassified. New measurement batches freeze matcher/version hashes. `replay_candidates.py` opens a campaign read-only and creates a separate versioned proposal report without modifying classifications, campaign settings or historical measurements.

Description-only candidates still require metadata to reach a handler. This patch does not add an all-upload intake queue or recover generic titles whose metadata is never fetched. Promotional, history and family commentary remain content-review questions. Reported related-video links never inherit approval, prove an excerpt, infer format or trigger deduplication. The Alone parent-link evidence and media-truth labels remain unverified.

Validation: compare both adapters against all shared observed/boundary outputs and identical policy/metadata hashes; exercise pending-only database ingestion, preservation controls, exclusions, eligibility, recent/RSS admission and read-only replay. Pilot packaging includes the exact manifest and portable golden fixtures. Tests use local databases and controlled transports; no live YouTube request or deployment is part of this implementation check.
